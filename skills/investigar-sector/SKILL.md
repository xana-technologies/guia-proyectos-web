# Investigar el sector

Todo el detalle está en el flujo [`flujos/investigacion.md`](../../flujos/investigacion.md)
(las rutas de esta skill son relativas a su carpeta). **Léelo entero antes de
empezar**: la plantilla del informe está dentro.

El resultado son **conclusiones, no un catálogo de webs**. Y **nada visual**:
colores, tipografía o fotografía como estilo son de `xana:ordenar-referencias`.

## 1. Qué escenario es

| Escenario | Qué se hace |
| --- | --- |
| 🟢 El cliente trae análisis | Pasarlo a markdown respetando lo que dice; sus conclusiones **mandan**. Completar las fichas; lo añadido va marcado *(añadido)* |
| 🟡 Solo una lista de nombres | Analizar cada web con la ficha |
| 🔴 No hay nada | Proponer la lista de competidores (3–5 directos + por modelo) y **esperar a que Belén la confirme** antes de analizar |

Mira el cuestionario de arranque (tabla 2 y preguntas 3–4) y `docs/00-arranque/brief.md`.

## 2. Pasos

1. Guardar lo que mande el cliente en `docs/01-investigacion/material/`.
2. Buscar y analizar cada web con la ficha del flujo (quién es, secciones y
   orden, argumentos, pruebas, tono, llamadas a la acción, carencias, qué tomar
   y qué no). Cada web con **URL y fecha de consulta**.
3. Comprobar que las webs citadas por el cliente siguen existiendo.
4. Escribir las **conclusiones arriba**: qué contar, qué pruebas necesitamos,
   qué evitar, cómo diferenciarse y qué implica para la estructura. Cada
   conclusión dice de qué ficha sale.
5. Pasar a `CHECKLIST.md` las preguntas para el cliente.

## 3. Reglas que no se saltan

- Cifras y claims del competidor, como **«declara…»** y entre comillas; no se
  dan por verificados.
- Ninguna frase de un competidor pasa al copy. No se copian estructuras enteras.
- **Una diferencia que el cliente no puede sostener es una pregunta**, no una
  conclusión.
- Los competidores no se nombran en la web salvo decisión expresa del cliente.
- Si una web llama la atención por cómo se ve, se le pasa a Belén como posible
  referencia, fuera del informe.

## 4. Al terminar

- Recorre la checklist **01 · Investigación** del flujo.
- Pide a Belén que lo revise. El informe no va al cliente: le llega convertido
  en la estructura (`xana:proponer-estructura`).
